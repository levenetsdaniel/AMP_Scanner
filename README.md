# AMP Scanner

Исследование бинарной классификации пептидов: AMP и не-AMP. В основном пайплайне сравниваются логистическая регрессия и Random Forest на 32 признаках последовательности, собственный трансформер и замороженный ESM-2 с логистической регрессией. Отдельный эксперимент использует TF-IDF дипептидов, выравнивание BLOSUM62 и kNN. Главный вопрос проекта сейчас — почему качество на официальном PepAnno test заметно ниже, чем на случайной validation.

## Данные

Программа загружает [сбалансированные файлы AMPlify](https://github.com/BirolLab/AMPlify/tree/master/data) в `data/amplify/`: 6676 строк для обучения и 1670 строк официального test. Положительные примеры происходят из баз AMP, отрицательные выбраны из UniProtKB/Swiss-Prot; подробнее — в [описании датасета](https://pmc.ncbi.nlm.nih.gov/articles/PMC9896668/).

Также доступен [PepAnno AMP](https://bis.zju.edu.cn/pepanno/data/). Если `data/pepanno/pepanno_train.csv` или `data/pepanno/pepanno_test.csv` отсутствует, программа скачивает недостающий CSV с официальной страницы PepAnno. В исходном train 238 последовательностей имеют обе метки; загрузчик исключает все 476 конфликтующих строк. После очистки остаются 16 298 train и 3 072 test.

Основной пайплайн делит официальную обучающую часть на train/validation в отношении 80/20 со стратификацией и seed 42. На validation выбираются параметры моделей, эпоха трансформера и пороги. Официальный test не участвует в обучении, но уже просматривался в ходе исследования; новые решения, принятые после его просмотра, нельзя оценивать на нём как на полностью независимой выборке.

## Запуск

Проверено с Python 3.13:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.experiment
```

Для PepAnno:

```bash
python -m src.experiment --dataset pepanno
```

По умолчанию результаты AMPlify сохраняются в `outputs/simple/`, PepAnno — в `outputs/pepanno/`. Путь можно изменить через `--output`.

Команда с `--dataset pepanno` последовательно обучает все четыре модели и печатает таблицу test-метрик. `tqdm` показывает эпохи и батчи трансформера, а также извлечение эмбеддингов ESM-2. В соответствующем каталоге `outputs/` сохраняются модели `*.joblib` и `transformer.pt`, таблица `metrics.csv` и построчные оценки `predictions.csv`. При повторном запуске файлы перезаписываются. ESM-2 скачивается при первом запуске. Для CPU можно добавить `--device cpu`, для короткой проверки — `--epochs 1`.

Можно запускать этапы отдельно, сохраняя тот же `--output`:

```bash
python -m src.experiment train-baselines --output outputs/simple
python -m src.experiment train-transformer --output outputs/simple
python -m src.experiment train-esm --output outputs/simple
python -m src.experiment evaluate --output outputs/simple
```

Отдельный эксперимент с выравниванием и kNN на PepAnno:

```bash
python -m src.alignment_experiment --dataset pepanno
```

По умолчанию отбор 64 кандидатов из обучающей части делается по TF-IDF дипептидов (`--retrieval dipeptide`). Для сравнения можно использовать эмбеддинги ESM-2 (`--retrieval esm2`) или обычного трансформера (`--retrieval transformer`); второй вариант загружает `outputs/pepanno/transformer.pt`, обученный на том же разбиении. Путь к checkpoint можно указать через `--checkpoint`. Затем кандидаты ранжируются по глобальному или локальному выравниванию BLOSUM62. На validation выбираются режим и число соседей (1, 3, 5 или 11) по ROC-AUC, а порог — по F1. kNN взвешивает голоса нормированными оценками выравнивания. Поиск приближённый: `--candidates 128` расширяет список кандидатов; `--mode global` или `--mode local` ограничивает режим. Официальный test сравнивается с теми же 80% train, которые использовались при подборе. Каждый способ отбора сохраняет `validation_metrics.csv`, `metrics.csv` и `predictions.csv` в собственном каталоге `outputs/alignment_<retrieval>_pepanno/`. Полное попарное выравнивание для всего PepAnno в этот запуск не входит.

В [src/experiment.py](src/experiment.py) находятся общее разбиение, обучение и оценка; архитектура трансформера — в [src/peptide_transformer.py](src/peptide_transformer.py), базовые признаки — в [src/features_extractor.py](src/features_extractor.py), загрузка обоих датасетов — в [src/load_dataset.py](src/load_dataset.py). Старые результаты лежат в `artifacts/` и в текущем запуске не используются.

## Результаты PepAnno

Основной запуск на официальном test после выбора моделей и порогов по случайной validation:

| Модель | Test ROC-AUC | Test AP | Test F1 |
| --- | ---: | ---: | ---: |
| 32 признака + логистическая регрессия | 0.6381 | 0.6452 | 0.5501 |
| 32 признака + Random Forest | 0.6890 | 0.7019 | 0.5519 |
| Собственный трансформер | 0.7024 | 0.7264 | 0.5626 |
| Замороженный ESM-2 + логистическая регрессия | 0.7127 | 0.7271 | 0.5962 |

При случайном разбиении ROC-AUC трансформера на validation равен 0.9329, на официальном test — 0.7024. Пептиды длиной 71–100 составляют около 22% обучающей части и 53% test. Даже внутри этого диапазона ROC-AUC трансформера падает с 0.894 на validation до 0.624 на test. У длинных AMP из test также ниже приближённая плотность заряда `(K+R-D-E)/L` и меньше сходство с ближайшими обучающими последовательностями. Разница длин объясняет лишь часть падения качества.

В [ноутбуке анализа признаков](notebooks/pepanno_feature_analysis.ipynb) проверены 463 вычисляемых признака: состав аминокислот, физико-химические свойства, концы цепи, локальные окна, простые шаблоны и дипептиды. Группы и компактный список выбирались по CV внутри train. После переобучения на **всём официальном train** оценка на test получилась такой:

| Признаки линейной модели | Число | Test ROC-AUC | Test AP |
| --- | ---: | ---: | ---: |
| Текущие признаки | 32 | 0.6373 | 0.6444 |
| Компактный отбор | 20 | 0.6567 | 0.6642 |
| Лучший по CV полный набор групп | 458 | 0.6777 | 0.6916 |

Эта таблица относится к отдельному эксперименту: все три модели обучены на полном train и используют фиксированный порог 0.5 для пороговых метрик. Её значения нельзя напрямую сопоставлять с F1 основного запуска, где пороги выбирались на validation. Полный набор улучшил линейную модель, но не решил проблему переноса на длинные пептиды.

Отдельные запуски выравнивания + kNN на PepAnno с 64 кандидатами; режим выравнивания и `k` выбраны на validation:

| Отбор кандидатов | Выравнивание | k | Validation ROC-AUC | Test ROC-AUC | Test F1 | Test MCC |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Дипептиды, TF-IDF | global | 11 | 0.9120 | 0.7396 | 0.6344 | 0.4057 |
| ESM-2 | local | 11 | 0.9372 | 0.6995 | 0.6127 | 0.3386 |
| Собственный трансформер | local | 11 | 0.9297 | 0.7023 | 0.6242 | 0.3495 |

На этом известном test отбор кандидатов по дипептидам показал лучший ROC-AUC из перечисленных экспериментов. Это наблюдение требует проверки на новом наборе данных.

## Следующий эксперимент

Сформировать validation внутри официального train, группируя похожие последовательности так, чтобы близкие пептиды не попадали одновременно в обучение и проверку. На этом разбиении сравнить базовые модели и отдельно измерить качество для длинных (51–70 и 71–100 остатков) низкозарядных AMP. Группы и правила отбора нужно зафиксировать до оценки моделей; официальный test не использовать для настройки.

## Исторический результат AMPlify

| Модель | Test ROC-AUC | Test AP | Test F1 | Test MCC |

| Собственный трансформер | 0.9638 | 0.9666 | 0.9023 | 0.8090 |
